## 前言

最近通过 Agent 配置了一些自托管服务，包括邮件、相册、代码托管和监控等。此前我主要使用 Alpine，也写过一些[服务部署笔记](@/blog/serverstatus-on-alpine.md)。这次仍然使用现有服务器，由 Agent 完成大部分部署和配置工作。

我一直是个懒癌晚期患者，秉持着「能用就行」的原则。很多服务虽然想用，但考虑到查阅文档、配置环境和排查问题的时间，迟迟没有部署。这两天的体验改变了我的想法：只需说明需求，Agent 就能查阅文档、执行命令，并根据结果继续处理，效率远超我的预期。

## 自托管服务

这次部署和整理的服务主要有以下几类：

- 阅读和相册：Miniflux 用于阅读 RSS，Immich 用于管理照片。
- 邮件：Stalwart 提供邮件服务，Bulwark Lite 提供网页邮箱。
- 代码和 CI：Forgejo 托管代码，Woodpecker CI 执行构建和定时任务。
- 监控：Beszel 查看服务器资源，Gatus 检查服务可用性。

此外，通过 Pocket ID 为部分服务配置了统一登录。部署时根据项目情况使用系统软件包、Docker 或 Podman，Web 服务主要通过 Cloudflare Tunnel 提供公网入口。

相比启动一个容器，服务之间的配置通常更费时间。例如统一登录涉及客户端、回调地址和权限，服务启动后还需要检查实际访问情况。这些工作也可以交给 Agent 处理，最终配置和操作记录则保存在项目目录中，方便后续维护。

## 自动化与 APK 仓库

除了部署服务，我还通过 Agent 完成了一些小项目。

其中一个是域名自动续期。代码托管在 Forgejo，通过 Woodpecker CI 定时调用 API，检查域名并按需续期。最近手动触发的检查已成功完成，当时没有需要续期的域名。后续主要关注任务是否正常执行，无需再定期进入面板检查。

另一个是自建 Alpine APK 仓库，将 zram 的 OpenRC 服务、Komari 等整理成软件包，通过构建流程生成包和索引，再由 Nginx 提供下载。这样可以直接使用 apk 安装和更新，减少在不同服务器上重复配置的工作。

这次还将仓库入口迁移到 Woodpecker 所在的服务器，验证了两个架构的软件包签名，并处理了 Cloudflare 对索引的缓存问题。这些细节如果由我手动处理，可能又会停留在「能用就行」的程度。

Agent 像是一个许愿机。提出想法后，它就能开始查阅资料、编写配置并调试，原本一直搁置的事情很快就有了结果。虽然有时需要补充说明和纠正，但对我而言，这已经是很大的变化。看完这两天的操作，我甚至想感叹：人工运维的时代已经结束了。

## 数据安全

自托管似乎进入了一个新的时代，但数据安全问题也变得更加严重。相册、邮件、代码和登录入口集中在自己的服务器上，Agent 一旦获得管理权限，也可能接触到其中的全部数据。误操作、凭据泄露，以及私人数据被发送到模型服务商的风险，都需要考虑。

另一个担忧是，我可能逐渐失去独立维护这些服务的能力。Agent 执行命令的速度很快，我未必理解每一步。即使配置保存在自己的仓库中，也不代表没有它就能完成排错和恢复。

因此，我仍希望保留完整的配置和操作记录，凭据单独保存，删除数据和迁移服务前由自己确认。同时，备份和恢复方式也需要自己了解，不能完全依赖 Agent。

我还会继续使用它，但对于应该交给它多少权限和数据，目前没有明确的答案。这一切变化得太快了。
